# LinkedIn AI Auto Job Applier

A local app that applies to LinkedIn jobs for you. It searches with your filters, scores each job against your profile with AI (Claude or GLM), answers the Easy Apply questions and submits. You edit every setting in a web UI, watch the bot's Chrome live in the browser, step in when it needs you (captcha, 2FA, a question it can't answer), browse your application history, and copy follow-up emails for HR addresses it found in job descriptions.

Everything runs on your machine with Docker. Nothing is exposed beyond `localhost`.

## Quick start

Prerequisites: [Docker Desktop](https://www.docker.com/products/docker-desktop/) (Apple Silicon or Intel/AMD), `make` and `openssl` (both come with macOS and most Linux distributions).

1. Get the code and create your `.env`:

   ```sh
   git clone <this repo> applier && cd applier
   cp .env.example .env
   ```

   In `.env`, fill in your LinkedIn login (optional) and the API key of your AI provider (see [below](#secrets-and-the-env-file)). Leave the other values empty: they are generated.
2. Start the app:

   ```sh
   make up
   ```

   This generates the UI password, the session key and the database password (when empty), builds the images (a few minutes the first time) and starts four services: the web UI, the API, the bot worker and Postgres. Without a `.env`, `make up` creates one from `.env.example`.
3. Open <http://localhost:8080> and log in with the `UI_PASSWORD` value from `.env`.
4. Configure the bot in **Settings**: your details, answers, search filters, AI provider and email template. If you have a settings file exported from another install, use **Import settings** instead. Upload your resume under **Settings → Secrets & resume**.
5. Press **Start** on the dashboard.

Every setting starts empty or generic, so fill in at least your name, phone number and search terms before the first run.

## Secrets and the `.env` file

Passwords and API keys live only in `.env`. They are never stored in the database, never shown in the UI (Settings shows "set" or "not set") and never written to logs. `.env` is git-ignored; `.env.example` lists every variable.

| Variable | What it is |
| --- | --- |
| `UI_PASSWORD` | Password for the web UI. Generated by `make up` when empty. |
| `SESSION_SECRET` | Signs the login cookie. Generated. |
| `POSTGRES_PASSWORD` | Database password, used only inside Docker. Generated once; don't change it afterwards. |
| `LINKEDIN_USERNAME`, `LINKEDIN_PASSWORD` | Optional. Without them you log in yourself in the live browser, once: the Chrome profile is kept between runs. |
| `CLAUDE_API_KEY`, `GLM_API_KEY` | The key for the AI provider chosen in **Settings → AI**. |
| `TZ` | Time zone for dates in the history, for example `America/New_York` (default `UTC`). |

After editing `.env`, run `make up` to restart the services with the new values.

## Coming from the original Auto Job Applier

If you used the script version ([Auto Job Applier](https://github.com/GodsScion/Auto_job_applier_linkedIn)), copy its `config/` folder, and `all excels/` and `all resumes/` if you have them, into this folder (all three are git-ignored). Then `make seed` imports:

- settings from `config/personals.py`, `questions.py`, `search.py`, `settings.py` and the non-secret part of `secrets.py` (the files are parsed, never run);
- history from `all excels/all_applied_applications_history.csv`, `all_failed_applications_history.csv` and `email_apply_jobs.csv` (the last one becomes the HR email list);
- your resume from `all resumes/default/resume.pdf`, if you haven't uploaded one yet;
- secrets from `config/secrets.py` that are missing in `.env` are added to `.env` (it prints their names, never the values).

`make seed` is safe to run again: rows aren't duplicated, broken CSV rows are counted and skipped, and settings already in the app (for example ones you changed in the UI) are kept. To replace them with the values from `config/*.py`, run the seed with `--overwrite`:

```sh
docker compose --env-file .env -f docker/compose.yaml run --rm -v "$PWD:/legacy:ro" api python -m app.seed --source /legacy --overwrite
```

## Using the app

- **Dashboard**: Start and Stop, what the bot is doing (applied, failed and skipped counts for the run), whether LinkedIn is logged in, the live browser and the run's log as it happens. If the last run failed, the error is shown here.
- **Settings**: every setting the bot uses, grouped as Personal, Questions, Search, Bot, AI and Email. Changes apply to the **next** run (a running bot keeps the settings it started with). Under **Questions → Your answers** you can add answers for questions by matching text, for example "German" → "None". **Email** holds your name, phone number and LinkedIn profile and the follow-up email template (placeholders `{my_name}`, `{phone_number}`, `{linkedin_profile}`, `{job_title}`, `{job_url}`, `{hr_email}`), with a live preview. **Export settings** downloads every setting except secrets as `applier-settings.json`; **Import settings** loads such a file, for example on another computer. An import checks the whole file first and saves nothing if any value is wrong. **Secrets & resume** shows which secrets are set and where you upload your resume (PDF, DOC or DOCX, up to 2 MB).
- **History**: applications sent and jobs skipped or failed, with search, date filters and CSV export (same columns as the old spreadsheets).
- **Emails**: HR addresses found in descriptions of jobs that passed your AI match score. **Copy** opens the composed email (recipient, subject and body, each with its own copy button; the body keeps its links when pasted into Gmail). When you close it, the app asks whether you sent it, and **Yes** marks it as emailed. The app never sends email itself.
- **Questions**: questions the bot couldn't answer. Type an answer and it's added to your answers, so the bot stops pausing on it.

## When the bot needs you

The bot pauses instead of guessing when it hits a captcha or 2FA, a question it can't answer (with "Pause at failed question" on), the "Pause before submit" check, or a search filter LinkedIn didn't apply. The dashboard then shows an amber **"The bot needs you"** banner (and a browser notification if you allowed them). Do what it asks in the **live browser** (click inside it to control Chrome), then press the banner's button, for example **Done, continue**. **Stop** ends the run at any point, including while it's waiting.

The live browser is also available full screen at <http://localhost:8080/novnc/vnc.html?autoconnect=1&resize=scale&path=novnc/websockify>.

## Commands

| Command | What it does |
| --- | --- |
| `make up` | Build and start everything (creates `.env` on first run). |
| `make down` | Stop everything. Your data stays. |
| `make logs` | Follow the logs of all services. |
| `make test` | Run the backend tests (in the API container, against a separate test database) and the frontend tests. |
| `make seed` | Import `config/*.py`, CSV history and resume (see above). |
| `make migrate` | Apply database migrations (`make up` does this too). |
| `make shell-api`, `make shell-worker` | A shell in that container. |
| `make shell-db` | `psql` in the database. |
| `make backup` | Dump the database to `backups/<timestamp>.sql`. |
| `make restore FILE=backups/<file>.sql` | Restore a dump (stops the API and worker while restoring). |

## Backup and restore

History, emails and settings live in Postgres (Docker volume `applier_pgdata`). The Chrome profile (your LinkedIn login), resume and bot logs live in the `applier_data` volume.

```sh
make backup                                   # writes backups/20261023-101500.sql
make restore FILE=backups/20261023-101500.sql
```

`make down` keeps both volumes. `docker compose ... down -v` deletes them, including your history.

## How it works

```
browser ──► frontend (nginx, :8080 on 127.0.0.1)
              ├─ /           the React app
              ├─ /api/       ──► api (FastAPI): settings, runs, logs, history, emails…
              └─ /novnc/     ──► worker (noVNC), only after the login check
worker: Xvfb virtual display + Chromium + noVNC; starts the bot for each run
postgres: settings, runs and logs, prompts, history, HR emails, questions
```

- `backend/app/` is the API, the database models and migrations, the settings schema, the seed and the worker.
- `backend/bot/` is the bot (`runAiBot.py` and `modules/`, the original code with the changes below). Its `config/` modules no longer hold values: they read the settings snapshot the worker writes for each run, and the secrets from the environment.
- For each run the worker writes the current settings to a JSON file and starts the bot as a fresh process. That's why changes apply to the next run. Stopping kills the bot and its Chrome.
- The bot's dialogs go through the database. A pause becomes a prompt the dashboard shows, and your answer goes back to the bot.
- Chrome is Debian's native Chromium (arm64 on Apple Silicon) driven by undetected-chromedriver; the profile is kept on the data volume.

Changes from the script version: settings in the UI instead of `config/*.py`; history in Postgres instead of CSV files; dialogs in the web UI instead of desktop popups; only Claude and GLM as AI providers; the startup sponsor popup, `keep_screen_awake`, the setup scripts and the old Flask viewer are gone. Fixed: LinkedIn's new jobs page ignores most search URL filters, so the bot now reads back which filters were applied and sets missing ones (job type, remote, location, Easy Apply) on the page. It also stops at LinkedIn's "more results related to your search" list, which ignores your filters. The "Follow company" checkbox is now unticked before submitting (LinkedIn changed it), and the LinkedIn login no longer depends on the page's language.

## Development

Backend (Python 3.12):

```sh
cd backend
uv venv .venv && uv pip install --python .venv/bin/python -r pyproject.toml --extra dev
docker run -d --name applier-testdb -p 127.0.0.1:55432:5432 -e POSTGRES_PASSWORD=test -e POSTGRES_DB=applier_test postgres:16
TEST_DATABASE_URL=postgresql+psycopg://postgres:test@127.0.0.1:55432/applier_test .venv/bin/python -m pytest tests -q
```

Without `TEST_DATABASE_URL`, the database tests are skipped and the bot tests still run.

Frontend (Node 22):

```sh
cd frontend
npm install
npm test           # vitest
npm run dev        # http://localhost:5173, proxies /api and /novnc to a running `make up`
```

## Troubleshooting

- **"LinkedIn: logged out" or a login prompt every run**: log in once in the live browser and press **Done, continue**. Don't turn on **Settings → Bot → Safe mode**: it uses a throwaway profile.
- **A run failed**: the dashboard shows the last lines of its log. `make logs` shows everything; the bot's own log is `/data/logs/log.txt` in the worker (`make shell-worker`).
- **"… is not set in .env"**: add the variable to `.env` and run `make up`.
- **Port 8080 already in use**: stop whatever uses it, or change the port in `docker/compose.yaml` (`127.0.0.1:8080:80`).
- **Filters not applied**: the bot pauses with "Filters not applied" when LinkedIn refuses one. Set it by hand in the live browser and continue.
